# Desktop integration

Per-user (no root) desktop integration for Linux: a launcher entry, an
app icon, and file associations so double-clicking a Spectrum file boots
straight into the emulator.

    ./install-desktop.sh            # builds zx_go and installs everything
    ./install-desktop.sh ./zx_go    # installs an already-built binary
    ./install-desktop.sh --uninstall

## What gets associated

| Files | MIME type | Machine picked |
| --- | --- | --- |
| `.tap` `.tzx` | `application/x-spectrum-tap` / `-tzx` (system types) | 48K (auto-types `LOAD ""`) |
| `.z80` `.sna` `.szx` | `application/x-spectrum-z80` / `-sna` / `-szx` (system) | from the snapshot |
| `.rzx` | `application/x-spectrum-rzx` (system) | from the recording |
| `.trd` | `application/x-spectrum-trd` (system) | Pentagon 128 |
| `.nex` | `application/x-spectrum-next-nex` (ours, magic `Next`) | Spectrum Next |
| `.81` | `application/x-zx81-p` (ours) | ZX81 |
| `.80` | `application/x-zx80-o` (ours) | ZX80 |

The classic Spectrum types already exist in shared-mime-info, so
`zx_go-mime.xml` only defines the three the system lacks. `.p` and `.o`
are NOT associated — the system claims them for Pascal source and object
files — but `zx_go prog.p` still works from a shell (the extension picks
the ZX81 the same way).

An explicit model flag beats the extension: `zx_go --pentagon game.tap`.

The same positional argument works with `--headless`, so scripted runs
can do `zx_go --headless --frames=2500 --save-screen=out.png game.nex`.

## Notes

- The icon is generated by the binary itself (`zx_go --export-icon x.png`);
  there is no image asset to keep in sync.
- Spectrum Next boots need the NextZXOS system assets (licensed, never
  committed): launch zx_go once and pick Machine → ZX Spectrum Next to
  run the built-in installer, or configure the SD image path.
- macOS/Windows file association is not covered here (this script is
  XDG-only); the positional argument itself is portable.
